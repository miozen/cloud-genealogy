# P0-6 加密包与密钥恢复设计

状态：local 基线已验证；真实密钥保管与 remote 演练待明确授权。最后更新：2026-10-25。

## 已实现的本地包加密边界

`scripts/backup-crypt.mjs` 仅对已经生成的本地归档文件执行加密或认证解密：

- AES-256-GCM，随机 16 字节 salt 和 12 字节 IV；
- 使用 Node 22 内建 `scrypt` 派生 32 字节密钥（`N=16384, r=8, p=1`）；
- 信封包含格式版本、算法、salt 与 IV；认证 tag 与密文一同保存；
- 输入和输出都必须是显式路径，拒绝覆盖已有输出；认证失败或中断会删除临时输出；
- 口令仅由 mode `0600` 的临时文件传入，最短 16 字节；不会写入 manifest、归档、命令输出、Git 或环境变量。

该工具不生成归档、不上传对象、不读取 Cloudflare 凭据，也不提供远程开关。`npm run test:local-backup-recovery` 使用一次性测试口令验证正确解密、错误口令、密文篡改与“失败不留下输出”。测试口令在临时目录中删除，绝不是可用恢复密钥。

## 恢复密钥的运行原则

1. 真实口令由备份责任人通过批准的离线/密码管理机制生成；不得用源码、账号密码、Worker Secret 或 Git token 派生。
2. 备份包外仅保存非敏感的 `backupId`、创建时间、算法版本和口令保管位置标识；不保存口令本身。
3. 至少两位具名保管责任人分别确认恢复请求。当前实现是**双人操作流程**，不是密码学 2-of-2 或门限分片；任何持有完整口令的人都可解密，必须在正式启用前接受这一风险。
4. 每次真实 remote 备份后，将加密包复制到 Cloudflare 账户外的至少两个独立受控位置；包与口令绝不放在同一未受保护位置。
5. 口令轮换后应立即完成一次隔离恢复演练，并记录旧包的保留期、可恢复负责人和到期处置。不得通过“重新加密后删除旧包”来跳过演练。

## 恢复演练记录最小项

- backup ID、包 SHA-256、演练目标环境、开始/结束时间；
- 两位责任人的确认记录（身份信息不写入公开仓库）；
- 解密认证、manifest、迁移基线、D1/R2 对象与业务计数的结果；
- 失败原因、是否生成任何目标资源、清理结论；
- 演练后下一次演练日期及保管责任变更。

## 未覆盖与禁止事项

- 当前不提供门限加密、KMS、硬件密钥、自动口令轮换或将口令分发给具体人员的功能。
- 未得到单独授权前，不创建真实口令、R2 S3 token、测试 D1/R2 资源，不导出 remote 数据，不进行测试环境或生产恢复。
- 当前没有 `media_asset` 表；真实媒体备份仍必须等待 P2 确认稳定媒体 ID、对象键、SHA-256、大小、MIME 和退役状态。
