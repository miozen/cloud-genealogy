# 产品需求基线

## 1. 产品定位
为单一家族长期保存、整理和展示族谱、家族文化及活动的网页系统。面向电脑和手机浏览器。不是商业多租户平台，不引入付费会员和在线支付作为首期功能。

## 2. 用户界面
- 公开家族门户：家族简介、公开资讯、公告、云谱、云祠、相册、功德榜。
- 族人中心：登录、档案认领、授权内容浏览、反馈；认领不等于修改权。
- 管理后台：概览、管理成员、内容、云谱、云祠、收益、设置。
- 同一个 Vue 应用，路由级拆包；后台鉴权必须由服务端强制执行。

## 3. 内容与业务模块
| 一级菜单 | 功能 |
|---|---|
| 概览 | 人物、世代、房支、谱书、内容、待审核、存储用量统计 |
| 管理成员 | 账号、角色、档案认领、房支授权、审核 |
| 内容 | 资讯、通知公告、留言反馈、相册、圈子、评论、功德榜 |
| 云谱 | 世系总览、人物档案、房支、谱书资源、编修审核、数据管理 |
| 云祠 | 多座祠堂、祖先纪念、祖墓档案、碑文、祭文、活动、相册 |
| 收益 | 捐赠项目、收支台账、用途、公示；首期不做在线支付 |
| 设置 | 家族信息、字辈、隐私、权限、媒体配额、备份恢复、日志 |

## 4. 世系展示
### 传统吊线图（默认）
- **按世代横向分列**，同代人物沿竖向排列；连接线采用正交折线。
- 每个节点显示姓名和可选世次/排行/状态；点击后右侧展示人物编辑或只读资料。
- 逐支展开/收起；可从任意祖先定位并展示其后代；按房支、谱书、世次搜索。
- 节点布局不能因展开无关房支而无故改变兄弟排序；折叠只影响视图，不修改关系。
- 历史谱书视图按指定版本的来源关系展示，缺失或冲突须标记；不得用统一关系悄悄补齐原谱。
- 统一视图显示已审核的承谱关系；两个视图可比较差异。
- 参考截图为**交互与信息组织参考**，不复制第三方商标、素材或具体 UI 代码。

### 完整亲属关系图
- 以选定人物为中心，展示父母、配偶、子女、过继、收养等；不是简单把所有关系强行塞进一棵树。
- 数据与传统图共用人物及关系服务，布局策略独立。

## 5. 编辑规则
- 人物信息：姓名、谱名、字、号、性别、生卒、迁居、安葬、事迹、出处、照片、隐私。
- 原始日期文字保留，允许未知、模糊日期、农历和年号；不得强制转换为精确公历。
- 生父母、嗣父母、养父母、婚配、承谱父亲分别建模。过继不删除生父关系。
- 同一已发布统一世系中，人物至多有一个有效承谱上行父节点；允许缺失，不可形成循环。
- 配偶支持多段婚配、原配/继配及未知姓名；不得用单个 spouse_id 表示全部婚配。
- 同辈顺序优先审核排行，其次审核展示顺序；未知排行不得伪装为真实排行。
- 房支分血缘世系、地域迁居和管理分组，不能自动等同；修改始分祖应预览影响。
- 未接续人物按已知房支待接续/房支未知分别管理，不虚构连接。
- 高风险变更（承谱、过继、拆支、挂接、合并、删除）必须校验、预览、审计与可回退。
- 同名不自动合并；谱书来源人物记录允许尚未关联统一人物。

## 6. 审核与发布
- 草稿 → 待审核 → 已发布 / 驳回；正式世系只读取已发布修订。
- 原谱来源记录不可被统一世系的编辑覆盖；争议事实允许并存。
- 已发布修改形成新修订，保留操作者、理由、差异和出处；恢复旧修订形成新的发布记录。
- 普通内容与世系修改可复用审核基础设施，但规则独立。

## 7. 隐私和访问
- 游客仅看公开资料；在世人物默认非公开敏感字段；未成年人更严格。
- 账号与谱中人物分离，认领必须人工或可靠方式核验。
- 服务端执行对象级、房支级、字段级访问控制；前端隐藏不等于授权。
- 捐赠公示允许匿名、隐藏金额和范围限制。

## 8. 首期排除
不做原生 App、商业多租户、在线支付、自动古籍 OCR、复杂 3D 祠堂、全自动传统印刷排版、无限视频上传。
