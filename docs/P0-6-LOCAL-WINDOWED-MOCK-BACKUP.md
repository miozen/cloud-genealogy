# P0-6 本地冻结窗口与 mock 备份组合

状态：仅本机测试夹具，2026-10-31。无真实 Cloudflare 适配器，不读取凭据、不访问远程 D1/R2；远程 CLI 仍明确拒绝执行。窗口、时间、证据和备份数据均为合成输入，不能当作可信静默证据或恢复点。

## 组合与发布边界

`runMockBackup` 仅在现有 mock 函数内增加可注入的 fixture 步骤钩子，默认行为仍为原本 mock。`local-windowed-mock-backup.mjs` 将本地 SQLite 窗口模型与五个 mock 步骤绑定，每步开始及结束均校验窗口；一旦失效、操作抛错或模型重启，尝试不得继续。模型中的 `completed` 仅是夹具历史状态。

组合夹具独占创建本次临时输出根目录，先在 `.fixture-staging` 生成本地 SQL、对象和原有 v2 manifest；正常返回前先创建仅供测试的 `fixture-complete.json`，再在本地 SQLite 写事务持锁期间同步重命名为 `complete/` 并记录窗口完成。这样竞争的本地 SQLite 释放操作不能在最终检查和目录重命名之间提交；声明为异步或返回 Promise 的发布回调会被拒绝。已有输出目录会被拒绝且不会删除。

SQLite 与文件系统仍不是同一事务：若重命名后、SQLite 提交前进程被杀，`complete/` 和文件标记可能存在，但模型状态会回滚。`verifyLocalWindowedMock` 要求同时检查 SQLite `completed`、冻结/窗口 ID 和代次、标记、manifest 哈希，以及现有本地备份包验证器；只有文件标记或 manifest 不能算夹具完成。反过来，若数据库已完成但输出在后续失败中被清除，同样不能通过验证。这只约束使用该夹具校验器的本地调用方，不会改变原有通用 manifest 验证器，也不保证其他消费者遵守该协议。

## 故障覆盖

`npm run test:local-windowed-mock-backup` 最终执行 46 项且全部通过；对五个步骤分别注入解除、解除后重冻、证据到期、证据撤销和异常中断，检查本次临时输出清理、旧窗口失效，以及新冻结、新证据和新窗口的本地重试。还覆盖异步导出期间并发解除、同一路径竞争、下载部分失败、现有目录保护、发布前失效、文件篡改和远程 CLI 拒绝。

进程 SIGKILL 不会执行 `catch/finally`。子进程分别在导出、验证、最终步骤、发布前、重命名后提交前及提交后被终止；在受控测试中，监督器检查模型和目录状态，仅对自己创建的临时目录手工清理，再用新窗口重试。已发布且数据库完成的结果在丢失确认时保留，不覆盖重试。重命名后提交前的测试还验证竞争 SQLite 释放被锁阻止，重启后该半完成结果被夹具校验器拒绝。

## 限制与风险

- 模型对时间和停止证据的输入由测试调用方构造；对 SQLite 与本地文件系统的实验不证明真实 Worker、D1、R2 或跨服务原子性，也没有证明已签发 PUT 已排空。
- 强杀遗留目录不会自动清理；测试监督器拥有独立临时根目录，这不能推广为可操作其他目录的恢复工具。清理失败、掉电及不可信调用方/符号链接攻击尚未验证。
- 标记绑定 manifest 哈希，验包时重新验证包文件；证据哈希、标记或人工输入不构成平台授权、跨实例停写证明或真实远程备份恢复证明。
- 真实远程执行需要可信证据、冻结窗口与外部写者隔离、直传 PUT 收敛、加密保管及独立一次性授权；本轮未实现这些能力。
