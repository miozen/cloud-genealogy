# P0-2 人物、关系与来源状态

状态：进行中。最后更新：2026-10-23。

## 已完成：核心物理模型

- 0004_core_genealogy_model.sql 建立人物名称/事实/地点、谱书版本与原始记录、来源主张、来源到统一人物的可撤销人工映射。
- 建立统一世系、revision、亲属关系快照、承谱快照、房支与 revision 内成员归属。
- 来源关系主张与统一承谱快照为不同表；来源未映射时仍可保存，统一承谱不会回写或覆盖来源记录。
- 同名人物允许并存；未知父系不要求插入虚构人物；生父与嗣父可同时存于亲属快照，仅由承谱快照选择传统上行边。

## 实际验证

- npm run test:local-core-model 通过；使用独立 Wrangler local 状态，验证同名、来源主张、人工映射、生父/嗣父保留、承谱选择与多类型房支归属。
- 同一 revision 的双承谱上行边与重复血缘主房均由数据库唯一索引拒绝。
- 新增承谱 revision 预览服务：返回有效性、结构化错误、受影响子节点与边增删数；不写入 D1，未来草稿预览与发布事务复用同一规则。
- 新增发布指针与 D1 batch 发布服务：合法候选写入完整 immutable snapshot，再切换当前 revision 指针；旧 revision 不被更新。
- 管理员 revision 预览/发布/回退 API 已接入既有会话、CSRF 与 system.manage 权限；预览返回当前指针版本，发布与回退要求该版本。
- 0006 以指针版本和 D1 触发器防止陈旧编辑发布：仅首发可使用版本 0，后续发布必须匹配当前版本；冲突返回 `409 revision_conflict`，不会切换当前指针或写入新 revision。
- 本地 Worker/D1 集成测试确认缺失 CSRF 被拒绝、环路不写入、合法发布、回退发布和陈旧版本冲突被拒绝。
- 管理员可手工创建谱书、谱书版本和原始人物记录，并将一条原始记录人工确认映射到统一人物；重新确认映射会撤销旧映射，绝不改写原始记录。
- 管理员可为统一人物追加多种姓名和事实；设为主姓名时同步显示名。事实可引用已有地点或同时建立新地点，均带可见级别和审计。
- 管理员可在指定谱书版本内录入原始事实主张及原始关系主张；涉及的原始人物记录必须属于同一版本，主张不会直接改写统一人物或承谱快照。
- 原始事实/关系主张支持按版本读取、以新主张续接旧主张及软撤销；历史文本不被覆盖或删除。
- 统一人物详情可读取有效姓名和事实；非主姓名与事实可软撤销，主姓名必须先有替代姓名以保持显示身份稳定。
- npm run lint、npm run check（16 个测试）、npm run build 通过。
- 未使用 --remote，未访问 Preview 或生产 D1/R2。
