# P0-6 本地孤儿审阅：并发、篡改与人工处置边界

状态：2026-10-31，设计评审和 local-only 测试；下述人工流程是待决定方案，不是已批准的业务需求或现有处置能力。没有真实审批、删除入口或远程执行，未连接 Cloudflare。

## 证据能证明什么

审阅夹具对同一个登记 attempt 产生只读观察。它两次读取 SQLite 中的尝试、窗口和审计（比较审计 detail 但不输出），并在数据库复查前后检查固定目录和标记元数据。已知状态和审计动作采用允许值；未知动作或损坏记录拒绝，避免把数据库任意内容当作报告输出。路径实际访问失败时，权限错误映射为 `review_access_denied`，变化造成的路径消失等映射为 `review_snapshot_changed`；正常观察到固定路径不存在则报告缺失，均不泄露路径或文件内容。

受控子进程在数据库读取后或文件观察后暂停；另一个进程分别移动目录、删除标记、在 WAL 模式下修改既有审计详情，以及在数据库复查后删除标记。测试验证这些指定交错被拒绝，不追加清理完成记录。发生其他未观测到的变化时仍不保证能检测；两次 SQLite 只读快照和文件检查不是跨系统原子快照，最终检查后也可能发生变化。观察始终只表达当时的有限信息，无法授权任何处置。

报告中的 SHA-256 未使用密钥，不是身份认证、签名、可信时间戳或独立留存。故意移除 SQLite 审计防更新触发器并改写数据的测试展示：动作被改写后旧报告失效，但根据被改写数据库产生的新报告仍能通过当前的重新观察比较；仅改写未公开的审计 detail 后，旧公开报告也可能继续通过。数据库所有者还可以篡改整个夹具和触发器。因此结果中出现 `cleanup_completed` 不等于操作确实完成，审计触发器也不是防篡改信任根。

## 推荐但未批准的人工处置边界

1. **保持阻塞和隔离。** 固定路径缺失、所有权标记缺失或异常、权限不足、检查中发生变化、记录失真时都不能推定对象已删除、被移动、属于某人或可安全清理；不得仅凭报告改变恢复状态。记录待审阅原因并保留现有文件，直至另有明确决定。
2. **分离角色与证据来源。** 由受控监督者确认测试进程停止和私有目录隔离，再由独立审阅者检查记录、目标身份与用途。若未来需要可信留证，应单独评估独立于被审阅数据库和清理进程的签名密钥、可验证时间及追加保管；本项目目前没有这些能力，不能把同一目录中的哈希当作独立证明。
3. **单独审批任何改变。** 确认状态、审批保留/复制/清理、执行、结果复验和审计是不同决策；谁可审批、是否需要两人、证据保留期限和权限范围均尚未由用户确认。任何未来执行方案需重做身份、窗口、并发与副作用评审，缺少可信依据时继续阻塞。

选项权衡：只保存本地未签名观察最简单，但不能抗数据库所有者篡改；引入独立签名及外部追加保管可增强事后来源核验，但增加密钥管理、身份、可用性和实施成本，也不自动证明文件状态或停写。当前推荐保留只读观察和保守阻塞，待真实需求明确后再设计信任根，不新增服务或真实执行器。

## 限制

- 夹具依赖 Linux `/proc/self/fd` 和私有根目录。文件身份检查与最终系统调用并非原子，目录移动及敌对并发不能被完全排除；权限测试只在未以 root 运行时有效。
- 两次数据库比较只检查各自读到的状态；观察结束后或两次读取之间先改回去的变化未必可检测，稳定篡改更无法仅靠当前数据库检测。报告没有绑定独立的可信来源或过期时钟。
- 测试只操作隔离文件和 SQLite，未证明真实 Worker/D1/R2、跨实例停写、直传 PUT 排空或远程恢复正确性；不得启用 remote 或视为上线验收。
