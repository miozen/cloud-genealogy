# P0-6 管理员备份与恢复操作清单

状态：local 演练操作清单已确认；remote 操作须逐次获得明确授权。最后更新：2026-10-25。

本清单不包含真实口令、Cloudflare token、账户 ID、桶名或生产资源 ID。所有 `<...>` 均是操作者在受控终端中填写的值，禁止将其提交到 Git、终端共享记录或应用日志。

## A. 每次操作前

1. 记录 backup ID、操作者、目标环境、开始时间和本次原因；确认没有未授权的部署、迁移或数据写入。
2. 在干净工作区启用 Node 22，检查当前分支和以下本地基线：

   ```bash
   npm run lint
   npm run check
   npm run build
   npm run test:local-backup-recovery
   ```

3. 若任一验证失败，停止；不得用失败的代码或未通过预检的包操作 remote 环境。
4. 对 remote 操作，先取得本次环境、D1、R2、凭据范围和恢复窗口的明确授权；没有 `--remote` 授权就不得添加该参数。

## B. local 演练（已验证）

运行：

```bash
npm run test:local-backup-recovery
```

该命令仅在一次性临时目录使用 Wrangler local D1/R2，并验证：业务计数、D1 SQL、R2 对象、manifest、加密认证、错误口令/篡改拦截和恢复到全新 local 状态。它不能证明 remote 资源可恢复，也不能代替真实密钥演练。

## C. 受控 remote 备份（尚未授权、尚未实现）

在进入本节前，必须已经确认：备份责任人、两位恢复确认责任人、归档保留周期、独立保管位置、短时写冻结公告、最小权限读取凭据和测试恢复窗口。

建议顺序：

1. 启用经过实现和审计的逻辑写冻结；确认所有写 API 与上传均返回可解释的拒绝状态，读取不受影响。
2. 导出 D1 SQL；记录导出开始/结束时间和 migration 基线。不得把导出文件直接导入现有 remote 数据库。
3. 依据未来 `media_asset` 元数据清单下载 R2 对象；逐项核验对象键、SHA-256、大小、MIME 和稳定媒体 ID。当前无该表，故不得执行真实媒体备份。
4. 采集业务计数，生成 manifest，执行只读预检；任何哈希、计数、迁移或引用失败都应删除不完整临时包并解除冻结。
5. 将完整包归档并用 `npm run crypt:backup -- encrypt ...` 加密；真实口令不进入仓库或 shell history。复制包到 Cloudflare 账户外的独立保管位置。
6. 记录成功 backup ID、包 SHA-256、保管位置标识与写冻结解除时间；不记录秘密。

## D. 恢复前预检

1. 两位恢复确认责任人确认 backup ID、目标为独立测试环境、包 SHA-256 和恢复理由。
2. 仅在权限受限临时目录解密；解密失败、manifest 失败、迁移不匹配、对象缺失或计数不符时立即停止，不创建/修改任何 remote 目标。
3. 明确目标 D1、R2 桶与 preview/production 均不同；不存在可验证的独立目标时停止并申请资源创建授权。

## E. 测试环境恢复演练（单独授权后）

1. 创建新的空白测试 D1/R2；禁止导入现有 preview 或 production。
2. 导入 D1 SQL、恢复 R2 对象、执行外键检查、manifest 哈希/计数比对和应用授权冒烟检查。
3. 记录所有差异与清理结论。失败时销毁仅本次新建的测试资源；不得尝试覆盖已有环境来“修复”。
4. 仅当演练完整成功，才讨论正式恢复的候选资源和一次性 binding 切换授权。

## F. 正式恢复（最高风险，另行审批）

不得复用本清单作为生产授权。正式恢复前必须再次备份当前生产状态，并经独立审批确认新资源、影响预览、停写窗口、切换步骤、回退资源和审计记录。禁止用 `d1 execute --file` 或 R2 覆盖操作直接改写既有生产资源。

## G. 记录与保留

每次演练或真实操作至少记录 backup ID、环境、操作者、两位确认结果、开始/结束时间、包哈希、计数、对象结果、异常、清理结论和下次演练日期。至少保留三个经成功演练的恢复点；真实密钥、token 和用户数据不进入该记录。
