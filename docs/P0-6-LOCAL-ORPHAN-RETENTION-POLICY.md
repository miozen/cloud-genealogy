# P0-6 local-only 历史绑定容量与证据保留评审

状态：2026-10-31，仅设计评审和本机测试夹具；没有真实审批、业务执行或远程资源操作。下列策略取舍是建议，不是已确认的上线需求。

## 策略比较

| 方案 | 能力与代价 | 当前结论 |
|---|---|---|
| 满额或证据未知时拒绝新写，保留已知历史 | 不自动丢弃去重依据；容量耗尽或无法证明请求为新请求时，后续写入不可用。 | **本轮测试建议**，以可用性换取保守行为。 |
| 受控归档后腾出容量 | 可能恢复容量，但必须独立验证归档完整性、请求到绑定的映射、原子切换、异常恢复和保留责任；同库归档无法防止整库回滚。 | 仅待评审，没有实现、清理或删除接口。 |
| 独立持久锚点或防回滚证据 | 可能增强独立性，但须解决初始化信任、身份、密钥、可信时间、失效恢复和锚点自身回滚；单纯在同一可修改目录保存文件不足以证明独立。 | 仅待评审，没有选定服务或真实信任根。 |

## 保守测试门面

`scripts/local-orphan-retention-gate-fixture.mjs` 是仅供夹具调用的内存门面。每次查询或重试先检查监督器状态、账本摘要和容量；监督器未初始化、pending、失联、摘要漂移、绑定丢失或绑定不匹配时，将当前门面锁定并拒绝后续操作，不自动重置、驱逐或重建。若只发生满额，已有 witnessed 历史在证据仍匹配时可查询或同请求重试；无记录的查询返回 `indeterminate`，不是从未执行的证明。

因为当前没有不可回滚的独立历史证据，即使监督器显示 ready 且容量有剩余，这个严格测试门面对未知请求 ID 仍拒绝新签发和新消费。它因此不能作为正常生产写入接口；这里只实验“未知历史不误判为新请求”的行为。返回的历史依然标记 `review_required`、不判断挑战当前可用性、远程执行不可用，不构成审批。

容量与账本核验间仍有时间间隔；既有 witnessed 事务会再次核对锚点并由监督器限制容量。若交错发生变化，该门面在观察到指定锚点或证据错误后锁定。它不持有持久锁定记录：进程重建即产生新门面；锁定也不阻止调用同一用户可访问的旧接口或直接修改 SQLite。

## 验证与反例

测试在真实写满 128 条本地 witnessed 绑定后，检查门面保留既有历史、拒绝新操作而不改变账本；监督器失联、未初始化、pending、绑定丢失及观察后锚点变化均触发当前门面锁定。测试还展示：即使测试监督器后来恢复相同绑定或 bootstrap，已锁定的门面也不会自行解锁。

同时保留反例：数据库与绑定被故意回退，并通过 `test_rebase` 不安全地重置监督器后，新建门面不知道先前锁定。该门面仍将缺失历史视为 `indeterminate` 并拒绝新写，但同一测试进程绕过门面，调用旧 witnessed 接口仍能用同请求 ID 创建不同挑战。故本轮只改善**选用该门面的测试路径**，不能宣称系统级防回滚或强制证据保留。

测试监督器、数据库、进程和未认证 IPC 由同一用户控制；进程失陷、直接 SQL、旧入口、两份状态同时回滚、密钥失窃或恶意 bootstrap 均超出该门面的保障。没有真实持久锚点、外部归档、可信时间、双人审批或生产级恢复；SQLite COMMIT 内部中断和掉电未验证，远程执行保持禁用。

`npm run test:local-orphan-anchor` 包含容量、锁定、锚点失效、双份回退和绕过反例；原有 challenge、signature、recovery 和 mock 回归需独立执行。
