# P0-6 local-only 审阅挑战持久化测试夹具

状态：2026-10-31，仅隔离本机测试；不连接 Cloudflare、不读取真实凭据，没有业务 API、人工审批或远程执行能力。它不建立真实信任根，也不把验签成功作为删除授权。

## 设计与事务边界

`scripts/local-orphan-challenge-fixture.mjs` 在新建的私有临时根中使用本地 SQLite。创建时将随机测试 capability 的哈希、根目录设备/inode 和由调用方提供的 Ed25519 测试公钥指纹绑定到夹具；重开时复核。运行 ID、根 ID 和 attempt ID 是调用方提供的测试标签，不是对真实目录、环境或用户身份的证明。数据库保留挑战及预期上下文；私钥仅存在签名测试调用方的内存中，不存入数据库或通过子进程 IPC 传递。

签发挑战及 `issued` 审计在 SQLite 事务内写入。消费时，`BEGIN IMMEDIATE` 将竞争消费串行化：在事务内核对未消费状态、上下文、报告形状和签名，成功后将挑战标记已消费并写入唯一的 `consumed` 审计，再同事务提交。无效签名、错误上下文或未知挑战不消耗记录。提交前发生异常、审计写入失败或测试子进程被杀，事务回滚；提交后但调用方尚未收到结果时进程被杀，重开后挑战仍被拒绝。结果只表示测试挑战消费，不代表观察真实、新鲜、获审批或允许清理。

签名的密码学校验复用 `local-orphan-signature-fixture.mjs` 的无状态校验函数；原有内存挑战验证器仍独立使用该函数。SQLite 使用本地写锁及 FULL 同步设置；两次竞争、提交返回前后的 SIGKILL 仅验证所测试机器上的 SQLite/文件系统行为，未在 SQLite `COMMIT` 指令内部或掉电时注入故障。

## 数据库回滚反例和限制

测试在数据库连接关闭时复制已签发、未消费的 SQLite 文件作为旧快照，再消费挑战并关闭连接，随后用旧快照覆盖测试数据库。重新打开后，同一已被消费过的签名可以再次成功，证明 SQLite 的持久化与本地触发器不能防止数据库文件回滚或拥有者篡改。审计触发器仅阻止正常 SQL 更新/删除；数据库所有者能修改数据、结构、键指纹或替换整个数据库。

不含可信时钟、挑战过期、跨机器存储、防回滚单调计数、独立追加证据、签名者身份、公钥分发、吊销或真实双人审批。进程或密钥被攻破时仍可生成有效签名；输入观察可被伪造，签名后文件可能改变。`BEGIN IMMEDIATE` 期间执行验签会持有写锁，忙超时/拒绝服务和可用性不是生产级设计。测试根及 SQLite 的所有者被视为受控，路径检查不是对敌对本机进程的安全隔离。

若未来需要真实防重放，必须先确定独立于可回滚数据库的信任锚、密钥生命周期、恢复和失效策略，再审查本地与远端的故障模型；本轮仅展示问题，不选定或接入外部服务。

## 测试

`npm run test:local-orphan-challenge` 验证真实本地审阅报告签名、失败不消费、capability/公钥/路径拒绝、审计失败回滚、两个独立进程竞争、无效签名与有效签名竞争、提交前后强杀、重开以及旧快照重放反例。夹具审计仅供测试，不进入应用 readiness。

后续独立监督器摘要实验见 `P0-6-LOCAL-ORPHAN-ANCHOR-FIXTURE.md`；实验路径不会自动守护本夹具的原有 `issue` / `consume`，也不是可信防回滚机制。
