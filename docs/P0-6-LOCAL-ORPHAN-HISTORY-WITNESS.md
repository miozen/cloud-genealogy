# P0-6 local-only 幂等历史绑定与生命周期实验

状态：2026-10-31，仅隔离本机测试。没有人工审批、业务恢复接口或远程执行；不连接 Cloudflare、不读取真实凭据。这里的监督器摘要是测试证据，不是真实信任根。

## 测试绑定与保守查询

`scripts/local-orphan-witness-fixture.mjs` 增加独立的 witnessed 测试路径，不替换旧幂等接口。工作进程在账本写事务中计算请求 ID、操作类型、输入摘要、挑战和记录结果的固定域 SHA-256，并在 SQLite 提交前把绑定摘要与账本 before/after 摘要提交给监督器；监督器先保留 pending，只有 SQLite 提交后收到 finalize 才在自身内存中登记该请求的绑定。这个协议仍非跨进程原子事务：准备后中断保持 pending，查询和重试拒绝，不自动修复。

查询或同请求重试先检查账本锚点、结构约束和输入，再要求当前请求—挑战绑定与监督器内存记录匹配。数据库记录存在但绑定丢失、绑定不符，或绑定存在但数据库记录丢失时均拒绝；既有未经过 witnessed 路径的记录也不会被自动升级或从 SQLite 重建。正常返回标记 `historical: true`、`currentAvailability: not_evaluated`、`review_required` 和远程执行不可用；即使持有旧签名并能查询消费历史，也不表示挑战当前可用或允许任何业务操作。

监督器只在内存中保留最多 128 条绑定，没有过期、清理、导出、持久恢复或自动重建策略；满额时新绑定准备被拒绝并回滚测试数据库事务。监督器丢失后新进程默认未初始化，即使测试调用方手动以当前数据库 bootstrap，已有请求缺少绑定仍拒绝。这个保守策略牺牲可用性；不能推导为生产可用的保管、审阅或恢复方案。

## 同 scope 交换与失陷反例

测试对两个同 scope 的 witnessed 签发记录交换关联挑战，并使用明确标为 `test_rebase` 的不安全故障注入让账本摘要重新匹配；只要监督器原有绑定仍独立保留，witnessed 查询检测到绑定不符并拒绝，而旧非 witnessed 查询仍可能返回交换后的值。

但监督器不直接观察签发过程，绑定摘要是工作进程通过未认证 IPC 提供的。测试再用 `test_force_binding` 修改监督器内存中的绑定，便可让篡改后的历史通过；`test_forget` 也能模拟证据丢失。这些命令是故意暴露给本地测试的故障注入，不是权限系统或可部署 API。控制数据库、工作进程、监督器或它们之间通信的主体能够伪造或删除证据，数据库与锚点一起回滚、监督器重置和私钥失窃同样无法被此实验防止。未在真实隔离主体、独立可信存储或防回滚硬件上验证。

## 记录生命周期和未解决问题

无自动清理、延期或重建能力；数据库记录被删除但绑定还在时拒绝重新签发或查询。绑定丢失但数据库记录仍在时拒绝读取。**若记录和绑定都被删除或一起回滚**，本模型无法区分历史请求与从未发生的新请求；`not_found` 只描述当前测试视图，不能作为恢复或批准依据。监督器和数据库状态不匹配、pending、不可用或通信失败时继续阻塞，不盲目 bootstrap 或推进。

`npm run test:local-orphan-anchor` 覆盖 witnessed 并发、原历史与当前状态、证据/记录丢失、同 scope 交换、supervisor 重启、提交前后强杀、finalize 回复丢失和两个主体共同受控的反例。测试使用假身份和一次性密钥，不能证明真实文件、新鲜度、停写、直传 PUT 排空、可信时间或 Cloudflare D1/R2 行为；SQLite COMMIT 指令内部与掉电未验证。
