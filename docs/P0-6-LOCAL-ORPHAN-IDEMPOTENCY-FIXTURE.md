# P0-6 local-only 挑战请求幂等性实验

状态：2026-10-31，仅本机测试。无人工审批、业务恢复接口或远程执行；不连接 Cloudflare、不读取真实凭据。记录和查询结果不构成对删除、恢复或任何其他业务操作的授权。

## 测试契约

`scripts/local-orphan-idempotency-fixture.mjs` 对测试 `issue` / `consume` 接受 UUID 请求 ID，计算固定域、操作类型和完整输入的测试规范化摘要；签发输入为测试 scope，消费输入为完整签名 envelope。数据库对请求 ID 建唯一约束，记录操作类型、输入摘要、挑战及历史结果；挑战变更、既有审计和请求结果同一个 SQLite 写事务提交。请求表及 schema 纳入监督器账本摘要，成功结果都明确标记 `review_required` 和远程执行不可用。

在监督器 ready 且摘要一致时，同一个 ID、相同输入返回已有结果，不再产生挑战或重复消费；相同 ID 对应不同输入或操作类型拒绝。消费签名无效、挑战无效或已被其他请求消费时返回 `rejected`，不保留请求记录。并发调用由 SQLite 写锁串行化。测试门面进程提供专门的请求与查询操作；这些是实验入口，不取代以前的无锚点 `issue`/`consume`，也没有 OS 权限隔离。

查询需要相同请求 ID、操作和输入摘要，并在持有 SQLite 锁时检查监督器锚点；无记录返回 `not_found`，上下文冲突报错，pending、锚点丢失或不匹配均拒绝查询。查询不会写账本或解除 pending。请求结果是历史记录：例如签发结果中原挑战之后可能已经被消费，不能据此断言当前可用。该夹具没有调用者身份或保密授权；知晓请求及输入的本机调用者可读取记录中的测试挑战，不能作为生产查询接口。

## 响应丢失与不确定性

若监督器已确认 finalize，但回复丢失，账本和监督器通常仍匹配，按相同 ID 查询或重试可取回同一记录，避免该状态下的重复签发。若在准备后、提交前或提交后确认前中断，监督器保持 pending，查询和重试均拒绝；本轮不根据 before/after 摘要自动完成或撤销事务。客户端不得把超时、`not_found`、`recorded` 或 `accepted` 当作业务批准或证明观察真实。

测试使用独立进程竞争同一个签发或消费 ID、复用 ID 的内容冲突、无效签名、finalize 回复丢失以及提交前后 SIGKILL；针对每个明确状态检查审计及结果。被消费的请求在原 SQLite 文件和监督器状态保持时可重复查询；这不证明掉电或 SQLite COMMIT 指令内部故障的行为。

## 回滚反例与限制

测试复制提交前的旧数据库，完成一次签发后重启监督器并使用旧库重新 bootstrap；原请求记录消失，相同请求 ID 可签发另一挑战。这说明数据库和锚点被一起重置后，幂等性与历史不能单靠该数据库保证。监督器或调用者被控制、旧接口/直接 SQL 被滥用、公钥或私钥失陷也仍可破坏假设；触发器只是本地测试约束。测试没有可信防回滚存储、独立签名信任根、持久消息收据、真实审批或双人权限。

记录没有过期、撤销、容量清理或可信时间设计；测试规范化格式不是通用互操作协议。返回的 `not_found` 只表示当前匹配锚点的测试数据库未见该记录，不能证明请求从未发生。不能据此对远程资源执行任何操作。

`npm run test:local-orphan-anchor` 运行本轮并发、冲突、响应丢失和回滚实验；challenge、signature、recovery 和 mock 备份测试保持独立。
