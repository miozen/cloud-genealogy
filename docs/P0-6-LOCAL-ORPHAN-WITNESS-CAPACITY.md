# P0-6 local-only 历史绑定容量与同时丢失实验

状态：2026-10-31，仅本机隔离测试；未连接 Cloudflare、不读取真实凭据、不接入人工审批，真实远程执行保持禁用。监督器、数据库和 IPC 都不构成可信独立安全边界。

## 容量与事务

测试实际依次完成 128 条 witnessed 签发，填满监督器内存绑定。第 129 条签发和新的消费在监督器 prepare 被拒绝，本地 SQLite 事务回滚；测试核对账本摘要、挑战和审计数量未改变，已存在的历史结果仍可查询及同请求重试。未改变现有 128 的测试上限，没有新增驱逐、清理或重建机制。

`observeWitnessCapacity` 是只读测试观察：在 SQLite 锁内读取监督器状态、账本摘要比较结果及已用、pending 预占、上限和剩余数量，事务最终回滚，不返回绑定 ID 或摘要，也不推进锚点。输出始终是 `review_required` 且远程执行不可用。监督器未初始化时已用、预占和剩余均为 null（未知），不是零或可用空间；通信失败或不合法计数拒绝。即使显示 ready 和容量，仍不代表来源可信、挑战可用或可以进行业务操作。

测试在接近上限时分别于 SQLite 提交前后 SIGKILL 工作进程：监督器保持 pending，容量观察显示 127 已用、1 预占、0 剩余，旧历史查询和新操作继续阻塞。为精确控制交错，这两项测试用测试专用 `test_force_binding` 合成 126 条绑定，另有一条通过正常签发；它们不是 127 条真实业务记录。另一项使用 127 条合成绑定，在最后一条成功提交与 finalize 后丢弃回复：结果可用同 ID 历史查询，监督器显示 128 已用，新绑定被拒绝。

## 同时丢失与 `not_found` 反例

一项测试完成 witnessed 签发后，显式使用 `test_forget` 删除该绑定并恢复签发前的 SQLite 快照；在监督器仍持有较新账本摘要时，受控查询拒绝。测试再故意调用不安全的 `test_rebase`，让回退后的库与被篡改监督器重新匹配：同一历史请求会返回 `not_found`，且可重新签发不同挑战。这是刻意注入的失陷反例，不是授权的恢复步骤。

另一项实际 SIGKILL 监督器并恢复旧数据库：新监督器未初始化时查询和签发均拒绝；测试随后**故意**从旧库 bootstrap，复现同一请求的 `not_found` 和不同挑战。记录与绑定都丢失或一起回滚时，当前模型无法区分历史请求和新请求；`not_found` 不是从未执行的证明，也不能作为审批或删除依据。不能从当前 SQLite 盲目重置监督器基线。

## 剩余限制

- 绑定由工作进程通过无认证 IPC 提供；测试故障注入可以伪造、删除或重设监督器内容。旧无锚点入口和直接 SQLite 访问仍可绕过，数据库所有者、监督器或两者一起失陷时无法保证历史完整。
- 容量数仅反映监督器当次内存状态，不具备持久性、可信时间、保留期、清理、独立备份或真实认证；满额后需要外部设计，当前不自动解锁或驱逐。
- SIGKILL 在测试可控边界触发，没有证明 SQLite COMMIT 指令内部崩溃、掉电、真实跨实例停写、直传 PUT 排空或 Cloudflare D1/R2 语义。

`npm run test:local-orphan-anchor` 包含真实 128 条容量实验、近上限进程中断、只读容量证据及双份状态回退反例。所有结果仅供测试审阅，不授权远程执行。

后续仅测试用途的严格保留门面和方案比较见 `P0-6-LOCAL-ORPHAN-RETENTION-POLICY.md`；该门面不能阻止旧入口绕过，且内存锁定不持久。
