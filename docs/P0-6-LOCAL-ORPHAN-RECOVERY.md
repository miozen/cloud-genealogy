# P0-6 本地孤儿输出恢复夹具

状态：2026-10-31，仅供本地测试。没有命令行入口、Worker 路由或远端适配器；远程备份执行仍禁用。此夹具不是通用文件清理工具，也不是实际备份恢复或授权证明。

## 范围和所有权

夹具在操作系统临时目录下创建新私有根目录及 SQLite 日志，仅处理根据随机 attempt ID 派生的直接子目录。重新打开必须匹配根目录路径、设备/inode 和随机 capability 的摘要。监督器为已登记 attempt 创建目录并证明所有权：数据库记录 nonce 摘要和目录设备/inode，目录内标记绑定 nonce 和身份。恢复时检查目录身份、标记、允许的 mock 路径及文件类型，拒绝符号链接、硬链接、未知条目、替换目录、未知 ID、路径穿越和清理后路径重现。目录与数据库必须位于夹具私有根中，不能用此过程接管任意已有路径。

停止判断只是由本地测试监督器提供的布尔回调，不是可信的跨进程或跨实例停写证明。窗口仍持有时拒绝清理，只有本地窗口失效才允许；已完成窗口的输出予以保留并记录审计，保留不代表内容已通过验包。夹具清理不会影响应用 D1 历史或真实 R2。

## 状态、审计和故障

尝试经历 `planned → owned → cleaning → cleaned`，失败可进入 `failed` 后重试，完成窗口进入 `preserved`。SQLite 同事务记录持久化清理意图和不可更新、不可删除的审计；清理阶段再次持有 SQLite 写事务，复查文件和状态后执行本地删除并写完成审计，竞争恢复由数据库串行化。重复恢复只确认已有终态，不重复记完成审计。

文件删除与 SQLite 不构成原子事务：删除后、提交审计前中断时，持久化 `cleaning` 意图和缺失目录允许重试补记完成；清理失败且目录仍存在则记录失败、重新核验后可重试。若部分删除导致所有权标记丢失，或身份/内容发生变化，拒绝继续并等待人工审查。清理前审计失败不删除，删除后审计失败保留清理意图供重试；失败审计本身失败也保留意图。已计划但未完成所有权证明的目录不会被自动删除。

`npm run test:local-orphan-recovery` 覆盖所有权、路径及内容拒绝、清理失败、审计失败、幂等重试、两个恢复进程竞争，以及删除后审计前 SIGKILL 重启。本地 mock 备份子进程在验证及发布完成后被 SIGKILL，分别验证失效孤儿清理和完成输出保留。所有进程、数据和停止判断都是本地夹具。

## 未解决问题

- 本地私有目录和监督器独占是实验前提。检查与递归删除之间仍有文件系统 TOCTOU；代码未采用基于目录文件描述符的逐级删除，不能抵御能够并发篡改私有根的恶意本机进程，也不能作为真实清理执行器。
- 没有在递归删除中途强杀、模拟掉电或验证任意部分清理的可恢复性；标记丢失时有意停在人工审查。SQLite 和本地文件系统的实验不证明 Cloudflare D1/R2 的持久性与原子性。
- 本地恢复记录不接入 readiness，不证明写者停止、直传 PUT 排空、跨实例冻结或真实授权；远程执行保持禁用。
