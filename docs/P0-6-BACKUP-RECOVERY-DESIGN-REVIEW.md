# P0-6 备份与恢复设计审查

状态：设计审查完成，实施待确认。最后更新：2026-10-25。

## 1. 本次审查结论

P0-6 是上线阻断项，但当前仓库**尚未具备**可对 remote D1/R2 执行备份或恢复的功能：没有备份脚本、`backup_record` 物理表、媒体元数据表、R2 业务读写代码或 CI 工作流。`wrangler.jsonc` 仅声明 local、preview、production 的 D1/R2 binding；其中 production 资源 ID 仍为占位值。故本文件只确认实施边界，不能作为已完成备份、演练或生产可恢复的证明。

已确认的技术事实：

- D1 可由 Wrangler 导出为 SQL，并以 `d1 execute --file` 导入；远程导出会阻塞其他数据库请求，且含外键的数据导入需保证表顺序。[Cloudflare D1 导入与导出](https://developers.cloudflare.com/d1/best-practices/import-export-data/)
- R2 可经 S3 兼容 API 分页列举、下载对象；用于备份的凭据应仅授予目标桶所需权限。[Cloudflare R2 S3 API](https://developers.cloudflare.com/r2/get-started/s3/)
- 免费 Worker 的每请求 CPU 时间和子请求数有限，不能把遍历、下载、哈希并打包全量数据库及媒体的工作放进线上 Worker 或 Cron。[Cloudflare Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)

## 2. 已确认约束

- 备份是 D1、R2 媒体、manifest 与迁移基线的完整组合；修订回退和 `audit_log` 不能替代灾难恢复备份。见 `docs/ARCHITECTURE.md`、`docs/P0-0-DECISIONS.md`。
- 备份副本必须位于 Cloudflare 账户之外；同一 R2 桶的复制品不算异地备份。
- 任何恢复先在独立的空白测试 D1 和测试桶完成；不得直接覆盖 preview 或 production。
- 生产恢复前先产生当前状态备份、显示影响范围、二次确认并写审计；当前应用尚未实现这些入口。
- D1 迁移只允许前向、可重复的演进。`migrations/0013_allow_membership_items_for_new_branches.sql` 已明确：已应用迁移若需回退，必须以受控前向迁移处置，不能覆盖既有数据。

## 3. 推荐的最小备份包契约

每个备份为单独目录（随后可整体加密归档），不写入应用 R2：

```text
cloud-genealogy-backup-<UTC timestamp>/
  manifest.json
  d1/schema-and-data.sql
  r2/<object-key>              # 仅被媒体元数据引用的对象
  checksums.sha256
  restore-report.json           # 仅恢复演练后生成
```

`manifest.json` 至少包含：

- `formatVersion`、UTC 创建时间、工具版本、源环境名称（不记录 token/secret）；
- `gitCommit`、已纳入的 migration 文件名和 SHA-256、SQL 文件 SHA-256；
- 每个 R2 对象的 key、大小、SHA-256、MIME、引用媒体 ID；
- 每张关键表的行数及关键业务计数（person、lineage、revision、source record/claim、branch、账号/权限）；
- 对象总数、总大小、校验算法、加密信息的非敏感描述；
- `consistencyMode`、开始/结束时间及操作者标识。

不把 Cloudflare API token、R2 secret、session、密码哈希的明文衍生物或解密密钥写入备份包、日志或 Git。

## 4. 一致性策略与边界

D1 与 R2 不提供跨服务原子快照。仅“先导出 SQL、再下载整个桶”会因并发上传或元数据写入产生孤儿对象、遗漏对象或哈希不匹配，不能接受。

推荐 P0 实施一个短时、可审计的**逻辑写冻结**：

1. 管理员创建备份作业，应用先拒绝人物、关系、来源、媒体元数据及媒体上传的写操作；读取保持可用。
2. 在冻结期间导出 D1，按导出的媒体元数据清单逐页下载 R2 引用对象并计算 SHA-256。
3. 对 SQL、对象、迁移基线和计数做本地校验；失败即标记备份失败并解除冻结，不产生“成功”记录。
4. 仅在校验成功后，生成 manifest、加密归档、复制到 Cloudflare 账户外的保管位置，并解除冻结。

当前尚无媒体表或上传流程，故该方案不能现在实现“按引用对象”枚举；P2 媒体模型必须提供稳定对象键、内容哈希、大小、MIME 与 retired/deleted 状态，P0-6 实施才可接入。若备份先于媒体功能落地，R2 段应明确记录为“空对象集”，不得伪称覆盖未来媒体。

不推荐把备份循环实现在 Worker/Cron：它会受免费计划的 CPU、子请求、Cron 数量和执行限制影响，也会把高权限读取凭据置于运行时。推荐由管理员受控的本地命令执行 D1 导出与 R2 S3 拉取；未来如采用 CI，必须先单独确认最小权限 token、加密密钥托管、日志脱敏和保管责任。

## 5. 恢复演练与正式恢复

恢复分为预检、隔离演练和受控切换三步：

1. **预检（只读）**：解密到权限受限临时目录，校验 manifest 格式/版本、所有 SHA-256、SQL 文件、migration 基线、对象清单与包内计数；失败不得触发任意远程写入。
2. **隔离演练（可丢弃环境）**：创建空白测试 D1 和测试 R2 桶，导入 SQL、上传对象、运行外键检查与应用健康/授权冒烟检查，比对 manifest 的计数、对象哈希和引用完整性。测试资源与 preview/production 必须不同。
3. **正式恢复（单独授权）**：先做当前生产快照；将已经通过演练的恢复集导入新的候选 D1/R2 资源，完成复核后才通过一次明确批准的配置/部署切换。不得用导入命令覆盖现有生产数据库或桶。

恢复报告必须记录：备份 ID、操作者、目标环境、开始/结束时间、所有校验结果、计数差异、失败对象、是否切换，以及对应审计事件。`audit_log` 可记录恢复事件，但备份包与演练报告必须在应用外独立保存。

## 6. 验收与测试基线

实施后至少应提供：

- 不访问 remote 资源的 manifest 校验单元测试：缺字段、未知格式、迁移不匹配、篡改 SQL、篡改对象、重复 key、计数不符均失败；
- 一个独立 local D1/R2 fixture：导出、打包、恢复到全新 local 状态，并比较人物、关系、谱书、来源主张、revision、房支、账号/角色/范围、对象哈希和授权读取；
- 一次经明确授权的 remote **测试环境**恢复演练记录；不以 local 成功替代该验收；
- 失败注入：对象缺失、哈希不符、SQL 导入失败、外键失败和中断后重试，均不能修改既有目标环境；
- 至少保留三个成功恢复点，并定期重新演练最旧可用恢复点。

当前仓库只有 local D1 migration、认证与世系回归脚本；未覆盖上述备份基线。

## 7. 待用户确认的实施决策

| 决策 | 方案与推荐 | 影响 |
|---|---|---|
| 执行主体 | 推荐管理员受控本地命令；CI 作为后续可选项 | 本地方案最少凭据暴露；CI 需要单独的 token/密钥治理。 |
| 加密与密钥保管 | 推荐在包离开受控主机前加密，密钥不进仓库且至少两名受托人可恢复 | 未确认算法与保管责任前，不能自动生成可长期保存的真实备份。 |
| 节奏与保留 | 推荐每次远程迁移/媒体批量导入前后各一次，另行制定定期节奏；至少保留三个成功点 | 具体周期取决于可承受的数据丢失窗口与人工操作成本。 |
| 写冻结体验 | 推荐短时拒绝写入、允许读取，并在管理端明确告知 | 要新增受权状态与审计，不可仅靠人工口头约定。 |
| 正式恢复切换 | 推荐恢复到新资源后再切换 binding，不覆盖原生产资源 | 需要独立的资源创建与部署授权。 |

## 8. 下一步

在确认上表决策前，不创建高权限 token、不操作 preview/production D1/R2、不部署，也不实现恢复写入。确认后应先完成“离线包格式 + local fixture + 只读预检”切片，再由用户单独授权测试环境恢复演练；正式恢复能力和任何生产切换继续保持独立审批。
